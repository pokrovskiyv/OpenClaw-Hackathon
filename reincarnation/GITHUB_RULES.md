# GitHub Commit Rules

**ПРАВИЛА ДЛЯ КОММИТОВ В OpenClaw-Hackathon:**

1. ✅ Коммитить только в новую ветку, НЕ В master/main
2. ✅ Создавать PR сразу после коммитов
3. ✅ Накапливать всё в одном PR до подтверждения от Сереги
4. ✅ Названия веток: `openclaw-changes-{number}`

**ПРАВА ДОСТУПА:**
- ✅ МОЖНО читать любые файлы из репозитория
- ✅ МОЖНО создавать и редактировать файлы ТОЛЬКО в папке `reincarnation`
- ❌ НЕЛЬЗЯ создавать/редактировать файлы в других папках

**Workflow:**
- Создаём ветку: `git checkout -b openclaw-changes-{number}`
- Коммитим изменения только в папку `reincarnation/`
- Пушим и создаём PR
- Ждём подтверждения от Сереги, что всё смержено
- Только потом создаём следующую ветку

**КРИТИЧЕСКИ ВАЖНО: Обновление документации при изменениях**

🔥 **ПРАВИЛО №1:** Любые изменения в логике, скриптах, функциональности ДОЛЖНЫ быть отражены в `reincarnation/README.md`

**Что обновлять:**
- Новые скрипты → добавить описание в README.md
- Изменения в скриптах → обновить описание в README.md
- Новые команды → добавить в список поддерживаемых
- Новая функциональность → добавить в Core Capabilities
- Изменения в структуре файлов → обновить File Structure
- Новые зависимости → добавить в Prerequisites
- Новые конфигурации → добавить в Configuration Files

**Почему это важно:**
- README.md в reincarnation/ - это инструкция для воссоздания Веника
- Если документация не обновлена → невозможно воспроизвести систему
- Любое изменение логики без обновления README.md = ошибка

**Когда обновлять README.md:**
- После создания нового скрипта
- После изменения функциональности скрипта
- После добавления новых команд
- После изменения структуры данных
- После добавления новых зависимостей

**Пример:**
Создал новый скрипт `new_feature.py`:
1. Создал скрипт
2. Добавил описание в `reincarnation/README.md` (секция Script Files)
3. Протестировал
4. Закоммитил и запушил в PR
